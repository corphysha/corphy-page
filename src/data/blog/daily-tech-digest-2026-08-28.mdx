### 2. Cloudflare 最佳化 1.1.1.1 DNS 快取，省下 100TB 記憶體

Cloudflare 於 8/27 發表技術文章，詳述他們對 1.1.1.1 背後的 DNS 平台「Big Pineapple」做的五項 Rust 記憶體最佳化，讓每筆快取條目的佔用從 953 bytes 降到 420 bytes（-56%），全 fleet 合計釋放約 100TB 記憶體（相當於 130 台 Gen 13 伺服器的 RAM）。同時快取寫入吞吐量提升 43%（62.5 萬 → 89.3 萬 entries/s），查詢延遲下降 19%（828ns → 670ns）——省空間的同時還變快了。

**為何重要**：這是一篇教科書等級的「資料結構決定系統成本」案例。Big Pineapple 隨時維持 2,500 億筆 DNS 快取條目，每筆省 1 byte 就是全 fleet 250GB。五項最佳化包括：`Vec`/`String` 改 `Box<[T]>`、三個 section 合併為單一 buffer + u16 offset、Rust enum 對大 variant 改 boxing、記錄資料改 raw wire-format bytes 存放等，每一步都附 benchmark 與 trade-off 分析（如 NAPTR 反而變貴但因罕見而值得）。

來源：Cloudflare Blog（8/27）、GIGAZINE（8/28）、DNSNews（8/28）— 官方一手資料 + 兩個獨立報導。

### 3. mklinux v7.0-mk2 公開：一台機器裸機同時跑多個 Linux kernel

Multikernel Technologies 的 Cong Wang 於 8/25 在 Linux Kernel Mailing List 宣布 mklinux v7.0-mk2，這是多核心（multikernel）Linux 樹的首次公開發布。它讓一台實體機器在**沒有 hypervisor** 的情況下同時執行多個獨立的 Linux kernel：host kernel 擁有 CPU／記憶體／PCI 裝置池，透過 `kexec_file_load()` 把 spawn kernel 直接開進每個分割的硬體實例。Phoronix、LWN、It's FOSS、Linuxiac 皆已報導。

**為何重要**：與 VM 相比沒有 VM exit、沒有第二層分頁表、沒有裝置模型；與容器相比實例不共享 kernel，一個 kernel 的 panic 或漏洞無法波及另一個。實測在 dual-socket Xeon Gold 5418Y 上，檔案系統密集型工作負載（unlink、rename、stat、open）拆成兩個 kernel 後接近 2 倍線性擴展。目前僅支援 x86_64，尚未進入 mainline。這是「把 kernel 視為可排程資源」的架構實驗，值得長期追蹤。

來源：LKML 官方公告（8/25）、LWN（8/26）、Phoronix（8/26）、It's FOSS（8/27）、Linuxiac — 官方郵件清單 + 四家獨立媒體交叉驗證。

### 4. VS Code 1.135 推出 Agent Host Protocol：AI agent session 與編輯器視窗解耦

Microsoft 於 8/26 發布 VS Code 1.135，正式將 Agent Host 架構開放：agent session 改為在獨立程序（Agent Host）中執行，透過開放的 Agent Host Protocol（AHP，MIT 授權）與多個 client 溝通。Session 不再屬於任何視窗——關掉編輯器 session 繼續跑，多個視窗可以連到同一個 session，甚至支援遠端 host（SSH／dev tunnel）。Sessions 面板還能直接接續來自 Copilot CLI、Claude Code、Codex 等外部工具的 session。

**為何重要**：byteiota 的分析點出關鍵——這是 2016 年 LSP 的架構重演：LSP 讓編輯器共享語言伺服器，AHP 讓編輯器共享 AI agent。當 session 可攜且 agent-agnostic，編輯器從「session 的擁有者」降級為「session 的 client」，這直接侵蝕 Cursor 等編輯器 fork 以「原生 AI session」為賣點的護城河。AHP 1.0 尚未定案，現階段適合實驗而非上線依賴。

來源：VS Code 官方更新日誌與架構部落格（8/26）、byteiota（8/26）、Visual Studio Magazine（8/26）— 官方 + 兩家獨立分析。

### 5. Node.js 26.8.0 / 24.20.0（LTS「Krypton」）同步發布

Node.js 於 8/26 協調發布 Current 與 LTS 兩條線：Node 26.8.0 帶來 zlib 原生 Zip 支援、SQLite RAII 式資源管理、SIV 加密模式、`permission.drop` API 與 JSPI（WebAssembly JavaScript Promise Integration）；LTS 24.20.0 則以 AsyncLocalStorage 的 explicit scopes（結構化資源管理）與 runtime package maps 為重點。數小時後又緊急追發 26.8.1 修復 `node --version` 誤報 alpha 版本的 metadata bug。

**為何重要**：`node --version` 輸出錯誤版本號聽起來是小事，但會破壞所有依賴版本偵測的 CI 腳本與部署管線——這正是他們當天就發 26.8.1 的原因。JSPI 進入 Current 線代表 WebAssembly 與 JS 的同步互操作往前一大步；`permission.drop` API 則讓實驗性的權限模型更接近實用。生產環境應優先評估 LTS 24.20.0。

## 細節說明

### Cloudflare DNS 快取最佳化的技術細節

這五項最佳化值得逐一拆解，因為每一項都是 Rust 資料結構設計的直接教材：

1. **`Vec`/`String` → `Box<[T]>`/`Box<str>`**：快取條目存入後不可變，`Vec` 為未來增長預留的 capacity 完全浪費。8 個欄位各省 8 bytes（指標+長度+容量 → 指標+長度），合計每筆省 64 bytes，2,500 億筆即超過 15TB。
2. **Section 合併**：DNS 回應的 answer／authority／additional 三個 section 原本各自為 list；合併成單一 list 後用兩個 `u16` offset 標記邊界，取代每個 list 8-byte 指標 + 8-byte 長度，每筆省 28 bytes。
3. **Enum boxing**：Rust enum 的大小等於最大 variant——小小的 A record（4 bytes）被迫佔用 NAPTR 級距的 144 bytes。將大 variant 移到 heap 後，A/AAAA 每筆省 120 bytes（兩者占流量 80%+）；代價是 NAPTR 等罕見記錄反而多付一次 heap 配置，屬於划算的 trade-off。
4. **Raw wire-format 儲存**：記錄資料直接以 DNS wire format bytes 存進單一 `Box<[u8]>`（2-byte 長度前綴 + 原始 bytes），回應時 A/AAAA/TXT/DNSSEC 可直接複製、跳過逐欄位重新序列化，僅含 domain name 的 CNAME/NS/MX/SOA 仍需解析以套用 name compression。此步驟讓查詢延遲再降 5%。
5. **Scratchspace buffer**：用跨插入重複使用的暫存 buffer 建構資料，完成後一次性 `memcpy` 進單一配置，取代每筆記錄各自的 heap 配置，插入吞吐量因此提升 13%。

驗證方式同樣嚴謹：自訂 allocator 包裝 Rust `System` allocator 逐筆記錄配置量；benchmark 用與生產流量相符的分佈（56% A、25% AAAA、19% TXT）填充快取；生產環境以 p90/p98/p99 追蹤，p99 記憶體從 9.3GB 降至 5.3GB（-43%）。釋出的 100TB 將轉投資快取容量以提升命中率。

### mklinux 的架構與效能數據

mklinux 的核心設計原則是「spawn kernel 不應比裸機多付出任何代價」。實例以 device tree 宣告（寫入 `/sys/fs/multikernel/`），device tree overlay 可在**不重開機**的情況下於資源池與執行中實例之間搬移記憶體、CPU 與裝置。實例可關閉、回收資源、再以不同 kernel 版本重生。

效能驗證在 dual-socket Xeon Gold 5418Y（Sapphire Rapids、2×24 cores、SMT 關閉）上進行，`will-it-scale` process 模式 24 tasks 單 socket：一個 kernel 驅動 24 cores vs. 兩個 spawn kernel 各 12 cores——unlink1 從 300K/s 到 780K/s（2.60x）、rename1 1.69M/s（2.14x）、stat2 19.8M/s（2.10x）；而 getppid、futex、poll 等「控制組」工作負載維持 1.00x，證明加速來自 kernel 內部鎖競爭的消除而非測量假象。穩定性方面已通過長時間 soak loop：含 KASLR 與 5-level paging、spawn kernel panic 不會波及其他 kernel、實例的每顆 CPU 確認歸還 host 後才會重用。

與 KVM 的 2 vCPU 對比 benchmark 也已公布（Phoronix 有圖表）。官方明確的應用模式是「app-kernel 與 device-kernel 分離」：一個實例專門跑驅動與 I/O，應用 kernel 完全看不到裝置中斷。目前限制：僅 x86_64、未進 mainline（Phoronix 評估短期內不太可能），以及生態系工具（容器 runtime、orchestrator）都還不存在。

### Asahi Linux 7.2 進度報告的重點

M3 系列的突破在於三個硬體改動的逆向工程：Apple 從 M3 Pro/Max 起把 USB port controller 從 I2C 匯流的 CD3217（ACE2）換成 SPMI 匯流的 ACE3——開發者發現 ACE3 的暫存器集幾乎與 ACE2 相同，只是包了不同介面，補上 SPMI 支援後 USB 3.0 與 Thunderbolt 全線打通。音訊方面 M3 新增「High Frequency」decimator，需要新的濾波係數與更大的初始化訊息；webcam 則只是 M3 Max 跳過了一條驅動未預期的初始化訊息。

更前瞻的部分：M3 的 GPU/DCP 韌體 ABI 對準 macOS 14.8.3，DCP 顯示支援已接近 M1/M2（macOS 13.5 ABI）的功能等級，官方 release「數週內」就會宣布。M4/M5 的 bring-up 也同時展開——macOS 15.x 韌體包改了 NVMe 控制器初始化序列，Yureka 與 Sven 在 m1n1 與 kernel 兩側完成修正後 NVMe 已可運作，PCIe 裝置枚舉與多核開機 crash 也已解決。硬體影片解碼（AVD）方面，AVC/HEVC/VP9 在所有支援機器上可靠運作，透過 fork 自 Bootlin 的 VA-API→V4L2 Stateless 轉譯層接入桌面應用；direct scanout（解碼幀直送顯示控制器、GPU 完全斷電）的 Interchange framebuffer 格式已在 DCP 驅動與 Mesa 兩側接好，只等 KWin 把 AGX/DCP 視為 multi-GPU 而停用 DMA-BUF 的限制解除（Plasma 6.8 可能支援）。

### VS Code Agent Host 的協議設計

AHP 的架構核心是「host 擁有權威狀態，client 是可來可去的觀察者/控制器」。每個 client 訂閱以 URI 定址的 channel（sessions、chats、terminals、changesets），收到初始狀態快照後接有序 action 序列；斷線重連時補發遺漏的 action 或重新拿快照。Session 資料用「immutable state + pure reducers」保證多 client 同步的一致性。本地場景 host 是 VS Code utility process（message port IPC），遠端場景是獨立 server（JSON-RPC over WebSocket，`code agent host --tunnel`）。不同 agent harness（Copilot 用 Copilot SDK、Claude 用 Claude Agent SDK）透過 adapter 翻譯成共同 session model。Microsoft 已提供 Rust、TypeScript、Kotlin、Go、Swift 的 client library。

值得注意的取捨：VS Code 原本推進中的 sandboxing rollout（已到 50%）被主動調回 0%，官方說法是為了聚焦 agent host 與 Copilot harness 的高優先級投資——這在大型專案裡是很罕見的「公開降低另一條線的優先級」表態。
