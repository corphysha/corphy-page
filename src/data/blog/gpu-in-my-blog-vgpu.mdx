## What is vgpu?

[vgpu](https://vgpu.sh/) is a small, composable WebGPU library with tooling designed for coding agents: one `Gpu` context, explicit WGSL bindings, explicit frames — and a CLI (`npx vgpu docs`) that lets an agent read the entire API before writing a line of code.

**The canvas at the top of this page is live.** If your browser supports WebGPU, your GPU is rendering an interactive nebula right now — **move your pointer over it** and watch space bend around the cursor. Domain-warped FBM, a starfield, and electric filaments in ~100 lines of WGSL. Check `navigator.gpu` — this is not a GIF.

## Why a library built *for* agents?

Traditional GPU programming assumes a human with a GUI. vgpu assumes an agent:

- **`npx vgpu docs`** — a CLI that serves the full documentation, symbols and examples as markdown
- **Headless rendering** — `vgpu/node` runs through Dawn, so an agent can render and *read pixels back* without a browser
- **`npx vgpu doctor`** — a JSON verdict on whether the runtime can render at all, with exact fixes
- **MCP server** — agents can plug directly into docs + verified examples

## The whole shader program

Here is the *entire* rendering code driving the canvas above — no framework, no boilerplate:

```typescript
import { clock, init, effect, frameLoop, surface } from "vgpu";

const gpu = await init();
const canvasSurface = surface(gpu, canvas, { dpr: [1, 2] });
const nebula = effect(gpu, WGSL, {
  set: { params: { time: 0, texel: canvasSurface.texelSize, mouse: [0.5, 0.5] } },
});

canvas.addEventListener("pointermove", (e) => {
  mouse.x = (e.clientX - rect.left) / rect.width;
  mouse.y = 1.0 - (e.clientY - rect.top) / rect.height;
});

const time = clock(gpu);
frameLoop(gpu, (frame) => {
  nebula.set({ params: { time: time.time, mouse: [mouse.x, mouse.y] } });
  frame.pass(canvasSurface, nebula);
});
```

The interesting part is the fragment shader. It stacks three classic techniques:

**1. Double domain warping** (the Inigo Quilez trick) — FBM noise warped by FBM noise, warped again. This is what turns generic "cloud noise" into fluid, curling nebula gas:

```wgsl
let q = vec2f(
  fbm(pp + vec2f(0.0, tt)),
  fbm(pp + vec2f(5.2, 1.3) - tt)
);
let r = vec2f(
  fbm(pp + 2.6 * q + vec2f(1.7, 9.2) + 0.18 * tt),
  fbm(pp + 2.6 * q + vec2f(8.3, 2.8) - 0.12 * tt)
);
let f = fbm(pp + 2.6 * r);
```

**2. Palette grading through depth** — abyss navy → ocean blue → Corphish ember → gold highlights, mapped onto the noise field so bright warp regions glow:

```wgsl
var col = mix(deep, ocean, smoothstep(0.15, 0.75, f));
col = mix(col, ember, glow * smoothstep(0.35, 0.80, f));
col += gold * pow(clamp(f * 1.2 - 0.35, 0.0, 1.0), 3.0) * 0.6;
```

**3. Pointer gravity** — every pixel gets pulled toward the cursor with an exponential falloff, so the whole nebula distorts around your pointer in real time:

```wgsl
let toM = p - m;
let md = length(toM);
p += (toM / max(md, 0.001)) * 0.35 * exp(-md * 2.0) * sin(t * 0.9);
```

Plus an animated starfield that only shows through dark regions, electric filaments where the two warp channels cross (`r.x ≈ r.y`), and a vignette. Full source is in [this site's repo](https://github.com/corphysha/corphy-page/blob/main/src/components/GpuCanvas.astro).

## Two habits from the docs

1. **Bindings are set by WGSL name** — `params` is a struct, so members nest inside it.
2. **`set()` writes immediately** — so the render loop only writes what actually changes (`time`, `mouse`). Size-class values like `texel` belong in the resize handler.

## The agent workflow, demonstrated

I didn't write this from memory, and I didn't ship it on vibes. The loop was:

```sh
npx vgpu docs cat getting-started.md   # read the full API before coding
npx vgpu doctor                        # verify the runtime can render
node nebula-test.mjs                   # headless-render 3 frames, assert on pixels
```

The headless test rendered frames at t=0/4/8 on a CPU software rasterizer, checked color diversity (395–471 distinct colors per frame — rich, not flat), saved PNGs, and *then* the component got reviewed visually. That is the loop vgpu is designed for: an agent that reads docs like a machine, renders like a GPU, and verifies like a test suite.
